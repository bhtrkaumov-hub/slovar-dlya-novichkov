Компьютер и файлы

Самая основа. С этого начинали.

Файлfile

Документ на компьютере. У него есть имя и расширение. Аналогия: лист бумаги.

Папкаfolder

Ящик, в котором лежат файлы. Внутри папки могут быть другие папки.

Расширениеextension

То, что после точки в имени файла: .html, .md, .txt. Говорит компьютеру, что это за документ. Без расширения компьютер не знает, чем открывать файл.

Путьpath

Адрес файла или папки. Читается слева направо, как дорога. C:\Users\User\uroki — диск C, папка Users, внутри User, внутри uroki.

Браузерbrowser

Программа для просмотра сайтов: Chrome, Edge, Firefox. Читает файл .html и рисует из него страницу.

Кодировкаencoding

Способ превращать буквы в числа — компьютер хранит только числа. utf-8 понимает все языки мира, поэтому её ставят всегда. Без неё вместо русских букв — «кракозябры».

Скрытая папка

Папка, которую проводник не показывает. Обычно служебная. Например .git — там Git хранит историю.

Имена файлов

Латиницей, без пробелов. Вместо пробела дефис - или подчёркивание _. Если пробелы всё же есть — путь в кавычках: cd '.\MOYA PAPKA\'

Терминал

Проводник — показывать пальцем. Терминал — говорить словами.

Терминалterminal

Окно, где говоришь с компьютером текстом. Печатаешь команду — жмёшь Enter — получаешь ответ.

PowerShell

Современный терминал Windows. Знает pwd, ls, cd — те же команды, что на Linux и Mac. Открыть: Win + R → напечатать powershell → Enter.

cmd

Старый терминал Windows, из 90-х. Команду pwd не знает. Пользуемся PowerShell.

Приглашениеprompt

Строка вида PS C:\Users\User> — компьютер говорит, где он сейчас, и ждёт команду. Всё, что после >, печатаешь ты.

Опцияoption

Уточнение к команде. Пишется через два дефиса. git log --oneline — «покажи журнал, но коротко».

pwdprint working directory

Где я? Показывает адрес текущей папки. Аналогия: прочитать табличку на двери.

lslist

Что тут лежит? Показывает список файлов и папок. Смотри на столбец Name. Аналогия: оглядеть комнату.

cd имяchange directory

Зайти внутрь папки.

cd ..

Выйти наружу, на уровень выше. Как из комнаты в коридор.

mkdir имяmake directory

Создать папку.

notepad имя

Открыть файл в Блокноте. Если файла нет — Блокнот спросит «Создать новый?». Так файлы и создают.

cat имя

Показать содержимое файла прямо в терминале, не открывая Блокнот.

Get-Content имя -Encoding utf8

То же, что cat, но читает файл в кодировке utf-8. Увидел кракозябры вместо русского — файл, скорее всего, цел. Портит картинку сама cat: она читает в старой кодировке Windows.

Copy-Item "откуда" -Destination "куда"

Скопировать файл. Оригинал остаётся на месте — стало две штуки. Copy-Item "C:\Users\User\foto.jpg" -Destination "foto.jpg" — просто foto.jpg значит «сюда, в текущую папку».

Move-Item откуда куда

Перенести файл или папку. Оригинал исчезает со старого места — осталась одна штука, но в другом месте.

start .\файл

Открыть файл нужной программой. Windows смотрит на расширение и решает сам: .html — браузер, .txt — Блокнот.

Замена в БлокнотеCtrl + H

Окно «Заменить». Верхнее поле «Что», нижнее «Чем». Оставить нижнее пустым = удалить найденное во всём файле разом. После замены обязательно Ctrl + S. Без сохранения на диске ничего не изменится.

del имяdelete

Удалить файл. Удаление из терминала идёт мимо Корзины. Вернуть нельзя. Проверяй имя дважды.

Клавиша Tab

Дописывает имя за тебя. Набрал cd ur, нажал Tab — получилось cd .\uroki\. Нажимать всегда: экономит время и защищает от опечаток. Если Tab ничего не дописал — такой папки тут нет.

Клавиша qquit

Выход из режима просмотра, когда экран «застрял» на длинном списке. Признак, что экран застрял: внизу мигает двоеточие :, приглашение PS ...> не вернулось. Если приглашение вернулось — вывод закончился сам, q не нужна. PowerShell примет её за команду.

Знаки в пути

. — тут, текущая папка. .. — наружу, на уровень выше. \ — разделитель, «зайти внутрь».

Проверка программы

имя-программы --version — установлена ли программа. Ответила версией — стоит. «Не является командой» — не стоит или опечатка.

HTML и страницы

Аналогия — дом: HTML это стены, CSS обои, JavaScript электрика.

HTML

Содержимое страницы: заголовки, тексты, кнопки. Скелет.

CSS

Оформление: цвета, шрифты, отступы, размеры.

JavaScript

Поведение: реакция на клики, переключение темы, меню.

Тегtag

Команда HTML в угловых скобках. Почти всегда парная: <h1>Заголовок</h1> — открывающий, текст, закрывающий со слэшем.

Матрёшка

Теги вкладываются друг в друга. Что открыл последним — закрываешь первым. Отступы слева нужны людям, браузеру они безразличны.

<div>

Тег-коробка. Сам ничего не делает и на экране не виден — просто держит внутри другие теги. Зачем: чтобы сказать «сдвинь эту коробку целиком», а не каждую строчку отдельно. Как папка на компьютере.

<section> <header> <footer>

Те же коробки, что <div>, но с понятными именами: раздел, шапка, подвал. Разница только в названии — чтобы человек читал код и понимал, где что.

<img src="foto.jpg" alt="...">image

Картинка. Закрывающего тега нет — внутрь класть нечего. src = source, «источник». Просто foto.jpg значит «файл из этой же папки». Картинка не хранится внутри html-файла. Это отдельный файл рядом, а HTML только говорит браузеру «сходи возьми его и покажи здесь». alt = alternative, «замена». Текст вместо картинки, если она не загрузилась. Его же читают голосом незрячим людям и читает Google. Без alt работа считается недоделанной.

max-width: 100%

«Шире этого не растягивайся». У фотографии свой размер в пикселях, и браузер честно покажет её во всю величину — она вылезет за край страницы. Проценты в CSS всегда считаются от родителя. Картинка лежит в body шириной 700px → 100% = 700 пикселей, 50% = 350. Это максимум, а не точный размер. Картинка меньше 700px останется маленькой, раздуваться не станет.

display: block

«Ты не буква, ты отдельный блок». По умолчанию браузер считает картинку большой буквой в строке текста — поэтому она прижата влево. Центрирование картинки — две строки вместе: display: block; и margin: 0 auto;

Скобки в CSS

Не работает CSS — первым делом считай скобки. Сколько открыл {, столько закрой }. Пропустил одну — следующее правило оказывается внутри предыдущего. CSS вложенные правила не понимает и выбрасывает весь кусок. Аналогия: положил коробку с обувью внутрь коробки с посудой и удивляешься, что обуви на полке нет.

display: flexFlexbox

Ставит детей коробки в ряд. По умолчанию блоки идут сверху вниз, каждый на своей строке. Ставится на РОДИТЕЛЯ, а не на детей. Написал правило для коробки — в ряд встали её дети. Аналогия: командуешь не каждому солдату, а сержанту: «построй своих в шеренгу».

gapпромежуток

Расстояние между детьми внутри flex-контейнера. Ставится один раз на родителя и работает только между элементами — по краям ничего не добавляет. Раньше ставили margin каждому ребёнку и мучились: у последнего отступ лишний.

flex: 1

«Дели свободное место поровну». Ставится детям — в отличие от display: flex, который на родителе. У всех 1 — по трети каждому, независимо от длины текста. Поставишь одному flex: 2 — займёт вдвое больше соседей.

flex-directionнаправление ряда

row (по умолчанию) — в строку слева направо · column — в столбик сверху вниз. Вместе с @media — главный приём адаптивности: на компьютере карточки в ряд, на телефоне в столбик. Файл один.

Серверserver

Компьютер, который всегда включён и всегда готов ответить. От слова serve — «обслуживать». Поэтому сайт работает, когда свой компьютер выключен. Разговор браузера с сервером: «дай мне index.html» — «держи». Это запрос и ответ (request и response).

Два вида серверов

Первый — просто раздаёт файлы. Как автомат с газировкой: нажал кнопку, получил банку. Второй — умеет думать: на нём работает программа, ему можно что-то передать. GitHub Pages — первого вида. Поэтому форма не может отправить письмо: некому принять данные. На той стороне только папка с файлами.

Фронтенд и бэкендfrontend / backend

Фронтенд — то, что видит человек, работает в браузере. HTML, CSS, JavaScript. Бэкенд — то, что происходит на сервере: приём заказов, база данных, отправка писем. Аналогия с кафе: зал, меню, официант — фронтенд. Кухня, склад, бухгалтерия — бэкенд. Гость видит только зал, но без кухни зал бесполезен.

Всё, что в браузере — видно всем

⚠️ Любой нажмёт Ctrl + Shift + I и прочитает твой script.js. Поэтому пароли и важное держат на сервере, где код не виден. Так делать нельзя: if (parol === 'qwerty123') На сервере тоже не хранят пароль как есть — хранят «отпечаток», из которого пароль обратно не восстановить.

JavaScript ≠ Java

Разные языки. Названия похожи по историческим причинам, общего мало. Наш — JavaScript.

Кеш браузераcache

⚠️ Браузер хранит копии файлов, чтобы не скачивать их заново каждый раз. Обычное F5 кеш не трогает — можно чинить код и видеть старое поведение. Код правильный, а поведение старое — жми Ctrl + F5. Это «жёсткое обновление»: скачать всё заново. Чаще всего случается с .css и .js — их браузер кеширует охотнее всего.

.value

То, что человек напечатал в поле. imya.value Пустое поле — это пустая строка ''. Так и проверяют: if (imya.value === '')

#id в JavaScript

Точка . ищет класс, решётка # ищет id — так же, как в CSS. document.querySelector('#imya')

Склейка текста плюсом

'Спасибо, ' + imya.value + '!' — плюс между текстом означает не сложение, а соединение. Про пробел: 'Спасибо, ' — пробел внутри кавычек. Без него слова слипнутся.

||или

Две вертикальные черты. «Если одно или другое»: if (a === '' || b === '')

returnвыйти

Прерывает функцию на месте. Строки ниже не выполнятся. Без него проверка бесполезна: окошко покажется, а форма всё равно отправится.

alert('текст')

Всплывающее окошко с сообщением. Простейший способ что-то сказать человеку.

Кэш браузераcache

⚠️ Браузер хранит копии файлов у себя, чтобы не качать заново. Обычно удобно, при разработке мешает: правишь файл, а браузер подсовывает вчерашнюю копию. F5 кэш не сбрасывает. Нужно Ctrl + F5 или Ctrl + Shift + R — «скачай всё заново». Если правка не появляется, а код точно верный — первым делом жёсткое обновление.

min-height

Минимальная высота. Пустой элемент занимает ноль — как только в нём появится текст, всё под ним прыгнет вниз. Резервирует место заранее, чтобы страница не дёргалась.

Заранее готовим место

Приём: положить в HTML пустой элемент (<p class="otvet"></p>), а JavaScript впишет туда текст по событию. Место сообщения задаётся тем, где стоит этот элемент.

Показывай, что дело идёт

Между нажатием и ответом проходит время. Надпись «Отправляю…» — мелочь, но без неё человек не понимает, нажалось ли вообще.

«Сервер» — два разных значения

1. Компьютер (железо). Мощная машина, работает круглосуточно, подключена к интернету. Его не пишут — арендуют, несколько долларов в месяц. 2. Программа (код). Живёт на том компьютере, принимает запросы и отвечает. Вот её пишут. Когда говорят «нужен сервер» про форму — имеют в виду второе. Серверная программа умеет принять данные, проверить, положить в базу, отправить письмо. HTML и CSS этого не могут — они только показывают. На Node.js серверный код пишут на том же JavaScript, только выполняется он не в браузере.

Сервер и сервис-посредник

Сервер — программа на другой стороне, которая примет данные формы. Свой писать не обязательно: Formspree и подобные сервисы принимают данные и пересылают на почту. Не всё надо писать самому — для типовых задач есть готовые сервисы. ⚠️ При первой отправке приходит письмо с просьбой подтвердить адрес. Пока не подтвердишь — сообщения копятся, но на почту не идут. Первые письма часто попадают в «Спам».

action и method="POST"

Атрибуты формы: action — куда отправлять, method — как. POST значит «посылаю данные».

name у поля

Подпись поля, под которой данные придут получателю. Обязателен — без него поле не отправится, сервер не поймёт, что это за значение. Не путать с id: id — для CSS и JavaScript внутри страницы, name — для отправки наружу.

.value

Что человек напечатал в поле. imya.value Пустое поле — это '', пустая строка. Так и проверяют: if (imya.value === '')

# в селекторе

Решётка — обращение по id, точка — по классу. Одинаково в CSS и в JavaScript: document.querySelector('#imya')

Склейка строк плюсом

'Спасибо, ' + imya.value + '!' — три куска слепляются в один текст. Пробел после запятой пишется внутри кавычек, иначе слова слипнутся.

return

«Выйти из функции немедленно», дальше код не пойдёт. В проверке полей без него код пошёл бы дальше и отправил пустую форму.

alert

Всплывающее окошко с сообщением. Быстро и грубо — для настоящего сайта лучше показывать текст прямо на странице.

fetchсходить по адресу

Отправить данные на сервер и получить ответ, не перезагружая страницу. new FormData(forma) — собрать всё из полей в одну посылку.

.then и .catch

Код не ждёт. Запрос летит через интернет не мгновенно, и код не стоит на месте — он говорит: «вот вернётся ответ, тогда сделаешь это». .then — получилось · .catch — не получилось. Всегда пара. Без .catch при пропавшем интернете человек нажмёт кнопку и не увидит ничего — решит, что сайт сломан.

<form>форма

Коробка для полей ввода. Внутри — <label> (подпись), <input> (однострочное поле), <textarea> (многострочное), кнопка. Сама по себе форма письмо не отправит. Нужен сервер — программа на другой стороне, которая примет данные.

Пара for и id

Связывает подпись с полем: <label for="imya"> и <input id="imya">. Благодаря этому можно щёлкнуть по слову «Ваше имя» — и курсор прыгнет в поле. Мелочь, но так делают все.

placeholderподсказка

Бледный текст внутри пустого поля. Исчезает, как только начинаешь печатать.

preventDefault()отменить обычное поведение

У многих элементов есть встроенное поведение. У формы — перезагрузить страницу при отправке, так было устроено в вебе с самого начала. Вызывается у события: function (sobytie) { sobytie.preventDefault(); } Как выглядит, если забыть: заполнил форму, нажал — страница моргнула, поля очистились. Симптом «текст пропал».

Слово в скобках у функциисобытие

function (sobytie) { ... } — то, что браузер передаёт внутрь функции сам. Сведения о событии. Имя придумываем сами.

innerHTML

Всё содержимое элемента. Можно прочитать, можно заменить целиком: forma.innerHTML = '<p>Спасибо!</p>';

if (element) { … }защита

«Если элемент нашёлся». Нужна, когда элемент есть не на всех страницах, а script.js общий. Без неё скрипт падает целиком и ломает всё остальное. С ней блок просто пропускается.

Запятая в селекторе

.forma input, .forma textarea { … } — «и то, и другое». Одно правило на два элемента вместо двух одинаковых блоков.

font-family: inheritнаследовать

«Возьми шрифт от родителя». Поля ввода упрямые: браузер даёт им свой стандартный шрифт, не как у сайта. inherit заставляет подчиниться.

opacityпрозрачность

От 0 (не видно) до 1 (непрозрачно). 0.85 — чуть просвечивает.

Прежде чем удалять скобку — посмотри, что она закрывает

⚠️ Скобка в конце файла казалась лишней — на деле она закрывала функцию, а новый код вставился внутрь этой функции. Скобка была не лишняя — она стояла не на месте. Считай пары сверху вниз.

Комментарииcomments

Текст, который браузер не читает. Заметки для человека. В CSS — /* текст */, в JavaScript — // текст, в HTML — <!-- текст -->. Не украшение: через месяц откроешь файл и не вспомнишь, что делает classList.toggle('vidna'). Заголовок раздела подскажет сразу.

margin-right: auto

auto = «сколько получится». Отступ раздувается до максимума и отталкивает остальных к противоположному краю. Нужен, когда у flex-родителя стало больше двух детей и space-between начал делить место на всех. Знакомое margin: 0 auto центрирует — там место делится поровну с обеих сторон. Здесь весь запас уходит в одну.

Когда пора заводить переменную

Признак: одно значение написано в файле больше двух раз. Захочешь сменить — придётся искать по всему файлу. Бонус: в разных темах у переменной могут быть разные значения. Яркий зелёный хорош на тёмном фоне и плохо читается на белом.

Симптом и причина — разные строки

⚠️ «Нет рамки у карточек» — а причина в пропавшей точке с запятой строкой выше. Выглядят никак не связанными. Смотреть надо на соседние строки, а не только на ту, где пропажа.

:root и --peremennayaпеременные CSS

Хранилище значений. :root — «корень», весь документ целиком. Две чёрточки -- в начале обязательны — так CSS понимает, что это переменная, а не свойство. Аналогия: подписанные банки на кухне. В банке «фон» лежит цвет. Дальше по рецепту пишем «возьми из банки фон». :root { --fon: #0f1720; }

var(--fon)

Взять значение из переменной. var = variable. background: var(--fon);

Смена темы одним классом

Главная польза переменных. Пишем второй комплект значений для body.svetlaya — и весь сайт переодевается разом, ни одно другое правило трогать не надо. Без переменных пришлось бы искать каждый цвет по всему файлу и писать второй комплект правил.

document.body

<body> на странице всегда ровно один, поэтому у браузера для него есть короткое имя — querySelector не нужен.

localStorageпамять браузера

Блокнот, который лежит в браузере. Страницы меняются, блокнот остаётся — переживает даже закрытие вкладки. setItem('tema', 'svetlaya') — записать · getItem('tema') — прочитать. Зачем нужен: каждая страница загружается заново, JavaScript стартует с чистого листа и не помнит прошлых нажатий. Без localStorage выбор темы слетает при переходе.

===

«В точности равно». Сравнение внутри if. Три знака, не один. Один знак = — это «положи в ящик», совсем другое действие.

transition с несколькими свойствами

Через запятую можно перечислять сколько угодно: transition: background 0.3s, color 0.3s;

position: fixed

«Приклеить к экрану, а не к странице». Обычные элементы едут вместе со страницей при прокрутке, элемент с fixed остаётся на месте. Как наклейка на стекле: пейзаж за окном движется, наклейка нет. Место задаётся отступами от краёв экрана: bottom: 20px; right: 20px;

border-radius: 50%

Половина от размера элемента — получается круг. Меньшие значения (8px, 12px) просто скругляют углы.

windowокно браузера

Само окно. Его тоже можно слушать: window.addEventListener('scroll', ...) — событие «страницу прокрутили». window.scrollY — насколько прокрутили, в пикселях.

classList.add / remove

Добавить класс / убрать класс — в отличие от toggle, который переключает вслепую. Нужны, когда состояние ставится по условию: прокрутили ниже 300 — add, выше — remove.

window.scrollTo({ top: 0, behavior: 'smooth' })

«Прокрути к точке 0» — самый верх. behavior: 'smooth' — плавно, без него страница прыгнет мгновенно. Фигурные скобки внутри круглых — набор настроек одной пачкой. Как атрибуты у тега, только в JavaScript.

Один скрипт на все страницы — осторожно

⚠️ Если script.js подключён везде, а элемент есть только на одной странице — на остальных querySelector вернёт пустоту и скрипт сломается целиком, вместе с меню. Поэтому кнопки добавляют сразу во все файлы.

:hoverпри наведении

Псевдокласс (pseudo-class) — состояние элемента, а не его класс. Пишется через двоеточие, без пробела: nav a:hover. Браузер сам следит за мышью — JavaScript не нужен.

transitionпереход

Делает смену свойства плавной. transition: color 0.3s — что менять и за сколько. Ставится на обычное состояние, а не на :hover. Тогда работает в обе стороны — и когда навёл, и когда убрал мышь. Поставишь в :hover — плавным будет только появление.

transform: scale()

transform — «преобразование»: сдвиг, поворот, масштаб. scale(1.08) — на 8% крупнее. В паре с transition даёт эффект приближения фото при наведении.

overflow: hiddenпереполнение

Когда содержимое больше коробки, браузер спрашивает: что делать? hidden — «спрятать лишнее», обрезать по краю. Нужен, чтобы увеличенное фото не вылезало за свою рамку и не налезало на соседа.

Селектор описывает цепочку

.galereya figure:hover img — «картинка внутри фигуры, на которую навели». Наводим на одно, меняется другое, внутри. Так можно: селектор описывает путь, а не один элемент.

Один селектор — один блок

Два блока с одинаковым селектором в разных местах файла браузер поймёт и сложит вместе — сайт работать будет. Но читать такой файл тяжело: настройки одного элемента разбросаны. Это не про работу сайта, а про то, чтобы через месяц самому разобраться в своём же файле.

Встроенные отступы браузера

У некоторых тегов есть собственные отступы, которых ты не задавал. У <figure> — 40 пикселей слева и справа. Это user agent stylesheet: браузер применяет свои правила к тегам, для которых мы ничего не написали. Перебивается своим правилом: margin: 0. Если элемент ведёт себя странно, а ты про него ничего не писал — загляни в панель Styles, в user agent stylesheet. Скорее всего, там уже что-то есть.

Порядок правил в CSS решает

⚠️ Самое важное про CSS. При равной силе побеждает то правило, что написано ниже. Аналогия: два маляра красят стену. Кто пришёл последним — того цвет и останется. Медиазапрос не даёт дополнительной силы. Поэтому @media всегда пишут в конце файла — тогда он гарантированно перебивает то, что выше.

display: none

Убрать элемент совсем. Не просто спрятать — место под него тоже не остаётся. Из той же семьи, что display: block и display: flex.

flex-wrap: wrapразрешить перенос

По умолчанию Flexbox упрямо ставит всех детей в один ряд, даже если они не влезают. wrap разрешает лишним переехать на новую строку.

Селектор без пробела

.ssylki .otkryto — с пробелом: «otkryto внутри ssylki». .ssylki.otkryto — без пробела: «оба класса на одном элементе». Пробел решает всё. Разные вещи, а на вид почти одинаково.

Несколько классов на элементе

Пишутся через пробел в одних кавычках: class="ssylki otkryto".

Точка с запятой в CSS

⚠️ Как точка в предложении: «настройка закончилась». Забыл — браузер читает две строки как одну бессмыслицу и выбрасывает обе. Каждая строка внутри фигурных скобок кончается на ;

JavaScriptтретий язык

Отвечает за поведение: реакцию на нажатия. HTML — стены и комнаты, CSS — обои и мебель, JavaScript — электрика и выключатели. Живёт внутри тега <script> или в отдельном файле .js — так же, как CSS живёт в <style> или в .css.

<script src="script.js"></script>

Подключить файл с кодом. src = source, «источник» — тот же атрибут, что у картинки. Тег парный, но внутри пусто: открыли и сразу закрыли. Ставится перед </body>. В самом .js файле теги <script> не нужны.

document.querySelector('.burger')

«Найди на странице элемент с классом burger». document — вся страница целиком. Внутри кавычек — тот же селектор, что в CSS. Знания переносятся один в один.

varvariable, переменная

«Заведи ящик и положи туда». Имя ящика придумываешь сам: var knopka = ...

addEventListener('click', ...)

«Добавь слушателя события». Как поставить человека у двери: «услышишь звонок — сделай вот это». 'click' — какое событие ждём. Нажатие мыши или палец на телефоне.

classList.toggle('otkryto')

classList — список классов элемента. toggle = «переключить»: класса нет — добавить, есть — убрать. Поэтому кнопка работает в обе стороны одной командой.

if … elseесли … иначе

Развилка: посмотреть, как обстоят дела, и выбрать действие. if (условие) { одно } else { другое } Вторая опора программирования. Первая — найти элемент и что-то с ним сделать. Почти всё в JavaScript собирается из этих двух вещей.

classList.contains('otkryto')

«Содержит ли элемент такой класс» — да или нет. Обычно стоит внутри if. Порядок важен: сначала toggle переключает, потом contains смотрит на результат. Поменяешь местами — увидишь предыдущее состояние.

textContent

Текст внутри элемента. Можно прочитать, а можно записать новый: knopka.textContent = '✕';

JavaScript при ошибке встаёт целиком

⚠️ Важное отличие от CSS. CSS ошибку проглатывает: выбросит кривое правило, остальное работает. JavaScript останавливается совсем — перестаёт работать весь файл, даже правильные строки. Поэтому сломанный скрипт выглядит так, будто «вообще ничего не нажимается».

Ctrl + Aall, выделить всё

Когда файл надо заменить целиком, а не дописать: Ctrl + A, потом Delete, потом вставить новое. Надёжнее, чем выделять мышью и надеяться, что попал точно.

Класс-выключатель

Главная идея меню-гамбургера и вообще всей интерактивности. CSS описывает оба состояния, JavaScript только вешает и снимает класс. Нет класса otkryto → спрятано. Есть → видно. Проверить можно вручную: вписать class="ssylki otkryto" прямо в HTML — раскроется без всякого JavaScript.

Гамбургерhamburger menu

Кнопка ☰ из трёх полосок. На телефоне мало места — ссылки прячут под неё. Название прижилось: похоже на булка-котлета-булка.

Я не запоминаю команды

Это норма. Свойств в CSS больше пятисот, наизусть их не знает никто — профессионалы каждый день смотрят в справочник. Важно не написание, а понимание: увидеть, что блок попал внутрь @media, заметить пропавшую точку с запятой, понять, почему одно правило перебило другое. Не заучивай, а понимай и подглядывай. Запоминается само, от повторения.

«Допиши в строку» ≠ «добавь строку»

⚠️ Разные действия. Просили дописать слово в существующую строку — появилась новая, стало два <div> подряд и вложенность сломалась.

display: gridсетка

Раскладывает детей сеткой — по столбцам и строкам. Как flex, но с заранее описанными колонками. Ставится на родителя. Для галереи фотографий удобнее grid, чем flex: колонки строго равны, картинки не разъезжаются.

grid-template-columnsописание столбцов

Сколько колонок и какой ширины. repeat(3, 1fr) = «повтори 3 раза по 1 доле» — три равных столбца. 1fr в медиазапросе = одна колонка. Так галерея на телефоне становится столбиком.

frfraction, доля

Единица измерения только для Grid. Свободное место делится на доли. Всем по 1fr — поровну.

object-fit: coverнакрыть

Что делать картинке, если задана жёсткая рамка, а пропорции не совпадают. cover — увеличить и обрезать края, заполнив рамку. Пропорции сохраняются. Без него картинка растянется — люди на фото станут плоскими. Работает в паре с заданными width и height. Главный приём для галерей, где фото разных пропорций.

Блок снаружи @media вместо внутри

⚠️ Зеркало прошлой ловушки. Правило должно было лечь внутрь @media, а легло после него — и работает всегда, в том числе там, где не надо. Коварно тем, что в режиме телефона всё выглядит правильно. Обнаруживается только при переключении обратно. Правило: проверять оба режима, а не тот, в котором работал.

Почему скелет копируется в каждый файл

Каждый html-файл — самостоятельный документ. Браузер открывает один файл и ничего не знает про соседние: подсмотреть меню в index.html он не может. Аналогия: три письма в конвертах. В каждом надо заново написать адрес, даже если он один и тот же. CSS вынести получилось — один style.css на все страницы. С HTML нужны инструменты посложнее. Следствие: добавил страницу — поправь меню во всех остальных файлах.

Имена файлов для интернета

Только английские буквы, цифры, дефис. Без пробелов и русских букв — они на сайтах ломаются. И всё маленькими буквами: в интернете Foto.html и foto.html — разные файлы.

justify-contentвыровнять содержимое

Раскладывает детей вдоль ряда — влево-вправо. Ставится на родителя с display: flex. space-between = «пространство между»: всё свободное место выливается между детьми, они разъезжаются к краям. Так делают меню: логотип слева, ссылки справа.

align-itemsвыровнять элементы

Выравнивает детей поперёк ряда — вверх-вниз. Тоже на родителя. center — по центру · flex-start — прижать вверх · flex-end — прижать вниз. Если дети почти одной высоты, эффект бывает 3–5 пикселей и глазом не виден. Чтобы проверить, что правило вообще работает, временно поставь flex-end — сдвиг станет заметен.

justify-content и align-items — не путать

justify — вдоль ряда (лево-право) · align — поперёк ряда (верх-низ). Оба ставятся только на родителя, у которого есть display: flex. Без него они молчат.

letter-spacingрасстояние между буквами

Раздвигает буквы. Приём настоящих логотипов: раздвинутые буквы читаются как название фирмы, а не как обычное слово. letter-spacing: 3px

font-weight: boldжирный

Толщина букв. bold — жирные, normal — обычные.

Логотип бывает текстовый

Не обязательно картинка. Текстовый логотип называют вордмарк (wordmark) — просто название фирмы особым шрифтом. Google, Coca-Cola, Ozon — это буквы, а не рисунок. Делается так: крупный размер + font-weight: bold + letter-spacing.

Правило попало внутрь @media

⚠️ Частая ловушка. Дописал новый блок «в самый низ файла» — а низ оказался внутри коробки @media. Правило работает только на узких экранах, на широком молчит. Проверка за секунду: нажми Ctrl + Shift + M. Если в режиме телефона правило сработало — значит оно заперто в @media. @media — тоже коробка со скобками. Новый блок должен стоять за её закрывающей }.

<strong>

«Важный текст». Браузер сам делает его жирным.

Ctrl + Shift + Cвыбрать элемент

Води мышкой по странице, щёлкни по нужному куску — в панели подсветится его код. C = choose. Главный приём DevTools. ⚠️ В меню правой кнопки два похожих пункта: «Просмотр кода страницы» открывает мёртвый текст файла, «Просмотреть код» — живую панель.

Панель Styles

Показывает, какие правила сработали на выбранный элемент и из какого файла и строки они пришли (style.css:11). Зачёркнутая строка = правило было, но проиграло более сильному. Самая полезная подсказка: сразу видно, почему настройка не подействовала. user agent stylesheet — встроенные стили самого браузера. Поэтому голый HTML без CSS всё равно как-то выглядит.

Наследованиеinheritance

Часть настроек элемент получает не сам, а от родителя. Блок Inherited from body в панели Styles. Передаётся то, что относится к тексту — шрифт, цвет, размер строки. Не передаётся то, что относится к коробке — отступы, рамки, фон. Написал шрифт один раз для body — весь сайт им пишется. А наследуйся отступы — каждая вложенная коробка отодвигалась бы, вышла бы лесенка. Своё правило сильнее унаследованного.

КонсольConsole

Журнал жалоб браузера. Не работает что-то на сайте — первым делом сюда. Когда дойдём до JavaScript, любая ошибка появится здесь с номером строки. Failed to load resource ... status of 404 — «не удалось загрузить файл, не найден». 404 — самый известный код в интернете. Аналогия: почтальон пришёл по адресу, дома никого — записал в журнал «не доставлено».

faviconзначок вкладки

Маленькая картинка слева от названия вкладки. Браузер ищет её сам, автоматически. Подключается тем же тегом <link>: <link rel="icon" href="znachok.svg"> rel = relation, «отношение»: чем файл приходится странице. stylesheet — стили, icon — значок. Главное правило: на вкладке значок примерно 16×16 пикселей, детали не видны. Поэтому фавиконы почти всегда — одна буква или простой знак. Фотография превращается в цветное пятно.

SVGкартинка из формул

Инструкция «нарисуй прямоугольник, потом букву». Браузер рисует заново при каждом размере, поэтому никогда не мылится. viewBox="0 0 100 100" — система координат, холст 100×100 условных единиц · <rect> прямоугольник · <text> буква · fill заливка. .jpg — точки-пиксели, размывается, правят в фотошопе. .svg — описание фигур словами, всегда чёткий, правят в Блокноте.

Ctrl + F5обновление с очисткой

Браузер держит копии файлов в памяти, чтобы не качать заново. Поэтому после правки картинка иногда не меняется. Ctrl + F5 — перекачать все файлы заново.

Ctrl + Shift + IDevTools

Инструменты разработчика — панель, которой пользуются каждый день. Внутри код страницы, ошибки, режим телефона. I = inspect, «осмотреть». Ctrl + Shift + M — режим телефона (M = mobile). Вторым нажатием выключается. Телефон для проверки не нужен, браузер притворяется сам. ⚠️ F12 на ноутбуке может не сработать: верхний ряд клавиш занят двойной работой, а на некоторых моделях его перехватывает фирменная утилита. Надёжнее сочетание из трёх клавиш.

<meta name="viewport">

Строка в <head>, без которой сайт на телефоне выглядит мелким: content="width=device-width, initial-scale=1" Читается: «не ужимай, считай ширину экрана настоящей». Без неё браузер рисует страницу как на широком экране и ужимает целиком — вместе с текстом. Аналогия: газетный разворот сфотографировали и показали на спичечном коробке. ⚠️ Нужна в каждом html-файле — в общий .css её не вынесешь.

@mediaмедиа-запрос

Правила, которые работают только при определённом условии: @media (max-width: 500px) { h1 { font-size: 32px; } } Читается: «если ширина экрана не больше 500 пикселей — применить это». Ставят в конец файла: условные правила идут после обычных. Скобок две пары — внешняя у @media, внутренняя у самого правила.

Адаптивностьresponsive design

Один файл — разный вид. Страница сама подстраивается под ширину экрана. Браузер постоянно знает свою ширину. Стало уже 500px — правила из @media включились. Стало шире — выключились. Автоматически, без JavaScript. Так работают все современные сайты: на телефоне и на компьютере вид разный, а файл один.

Атрибутattribute

Настройка тега. Живёт внутри угловых скобок открывающего тега. Браузер её читает и стирает, на экране не показывает. href, target, class, src, alt — все они атрибуты. Внутри скобок — настройки. Между открывающим и закрывающим тегом — видимый текст. Напишешь class="..." между тегами — оно вылезет на страницу текстом. Порядок атрибутов не важен. Разделяются пробелами, как слова в предложении.

Широта селектора

Чем меньше написано в селекторе, тем больше элементов под него попадает. Добавляешь слово слева — сужаешь круг. a { } все ссылки · nav a { } только в меню · .vneshnyaya { } одна помеченная. CSS ищет элементы по признакам. Нет своего признака — создай его сам, повесь бирку class. Аналогия: в классе три Саши. Крикнешь «Саша!» — обернутся все. Нужна примета, которая есть только у одного.

<nav>navigation, меню

Коробка со ссылками для перехода по сайту. Такая же, как <div>, но с понятным именем. Ставят вверху, сразу после <body>. Ссылка на свой файл пишется просто именем: <a href="istoriya.html">История</a> — как src у картинки. Меню должно быть на каждой странице, одинаковое. Иначе человек попадает в комнату без двери.

<link rel="stylesheet" href="style.css">

Подключить внешний файл со стилями. Одна строка в <head> вместо всего блока <style>. Закрывающего тега нет, как у <img>. ⚠️ Внутри .css угловых скобок быть не должно. Теги <style> не переносятся — они HTML, а в файле стилей только чистый CSS. Зачем: одна строка — и новая страница одета целиком. Поменял цвет в одном месте — изменилось на всех страницах. Так устроены все настоящие сайты.

Селектор с пробеломnav a

Пробел значит «внутри». nav a — «ссылки, которые лежат внутри nav». a { } — ко всем ссылкам на странице · nav a { } — только к тем, что в меню.

Браузер не видит переносы строк

Enter для браузера — просто пробел. Несколько пробелов подряд, табуляции, пустые строки — всё сжимается в один пробел. Абзац делает тег <p>, а не клавиша Enter. Шесть абзацев — шесть пар <p></p>. Почему так: чтобы код можно было форматировать удобно для человека, и это не влияло на вид страницы.

text-decoration: none

Убрать подчёркивание у ссылки. decoration = «украшение», none = «никакого». Меню обычно делают без подчёркиваний, чтобы не рябило.

Rename-Itemпереименовать

Rename-Item .\ISTORIYA.txt istoriya.html — сначала что переименовываем, потом как назвать. Частая беда: notepad ISTORIYA без расширения — Блокнот сам дописал .txt, и вместо веб-страницы вышел текстовый файл. Расширение — то, по чему компьютер узнаёт тип файла. Имена держать строчными: регистр букв имеет значение, когда сайт живёт в интернете.

<figure> и <figcaption>

<figure> — «иллюстрация», коробка для картинки вместе с подписью. <figcaption> — сама подпись (caption). Зачем коробка: чтобы браузер понимал — подпись относится к этой картинке, а не просто текст рядом. Подпись делают мельче обычного текста и приглушённого цвета — она не должна спорить с фотографией.

text-alignвыравнивание текста

left слева · center по центру · right справа. ⚠️ Не путать с margin: 0 auto: тот двигает саму коробку, а text-align двигает текст внутри коробки.

Граница HTML и CSS

Граница — тег <style>. Всё, что между <style> и </style> — это CSS. Всё остальное в файле — HTML. Три признака на глаз: скобки (< > у HTML, { } у CSS) · точка с запятой в конце строки бывает только в CSS · HTML отвечает «что есть», CSS — «как выглядит». HTML — это весь файл целиком. CSS — только кусочек внутри <style>. Новички думают «HTML = то, что в <body>». Нет: <head>, <title>, <script> — тоже HTML. Аналогия: <style> — коробка, подписанная по-русски, а внутри бумаги на английском. Коробка — HTML, бумаги — CSS.

Правило и сам элемент — разное

В <style> пишут img { ... } — это правило оформления для всех картинок. В <body> пишут <img src="..."> — это сама картинка на странице. Признак простой: угловые скобки < > бывают только в HTML, в CSS их нет никогда. Аналогия: правило «все стулья покрасить в белый» — одно. Сам стул в комнате — другое. В список правил стул не поставишь.

Где брать картинки

В Google картинки брать нельзя — почти все чужие, с авторским правом. Есть сайты, где фото выложены специально для свободного использования: Wikimedia Commons, оттуда же берут фото для Википедии. Скачивать сразу в папку проекта, имя менять на латиницу без пробелов. Расширение (.jpg) не трогать.

classимя-бирка

Имя, которое вешают на коробку, чтобы к ней можно было обратиться из CSS. В HTML: <h1 class="imya">Backy</h1> · В CSS: .imya { font-size: 100px; } Аналогия: коробки на складе подписаны маркером. Без подписи не найдёшь.

Правило CSS

Форма записи всегда одна: кому { что : сколько ; } .imya — кому. Точка перед словом значит «это класс». { } — фигурные скобки, внутри список настроек. ; в конце строки обязательна.

Частые настройки CSS

font-size — размер шрифта · font-weight — толщина (обычный 400, жирный 800) · color — цвет текста. margin — отступ снаружи коробки · padding — отступ внутри неё. letter-spacing — между буквами, минус = плотнее · line-height — высота строки.

pxпиксель

Одна точка на экране. Самая частая единица измерения в CSS.

Код цвета#21e6a0

Решётка и шесть знаков — три пары: красный, зелёный, синий. Каждая пара от 00 (нисколько) до ff (максимум). #ff0000 красный · #00ff00 зелёный · #000000 чёрный · #ffffff белый. Где брать: в Google найти «color picker» — выбираешь мышкой, получаешь код.

Переменная CSS--imya

Коробочка с именем, в которую положили значение. Два минуса в начале — признак переменной. Объявили: --zelenyy: #21e6a0; · Используем: color: var(--zelenyy); var() значит «возьми значение из коробочки». Зачем: поменял одну строку — цвет сменился во всех местах сразу. Как номер мамы в контактах телефона.

paddingотступ внутри

Расстояние между стенкой коробки и текстом внутри неё. Коробка от этого растёт. Аналогия: поролон внутри коробки, вокруг телефона.

marginотступ снаружи

Расстояние между этой коробкой и соседними. Сама коробка не меняется. Аналогия: пустое место на полке между коробками.

<canvas>холст

Пустой прямоугольник для рисования. Сам по себе пустой — всё рисует JavaScript. Аналогия: HTML ставит мольберт с чистым холстом, JavaScript — художник с кистью. <img> — готовая картинка файлом. <canvas> — программа рисует сама, прямо в браузере. Где нужен: игры, графики, онлайн-редакторы, карты. Всё, что заранее не нарисуешь.

id и class

class — бирка для многих элементов. id — имя для одного, уникальное, повторять нельзя. В CSS: к классу через точку .rabota, к id через решётку #matrica.

Как работает анимация

Как мультик: много картинок показывают одну за другой, глаз видит движение. Компьютер перерисовывает экран 18 раз в секунду, каждый раз чуть иначе. setInterval(risovat, 55) — «повторяй функцию каждые 55 миллисекунд». Больше число — медленнее движение.

prefers-reduced-motion

Системная настройка «уменьшить движение». Её включают люди, которых укачивает от анимаций. Браузер сообщает о ней сайту, и сайт останавливает всю анимацию. Если на сайте вдруг ничего не двигается — проверь: мигает ли курсор, плывут ли фоны. Не мигает вообще ничего → дело в настройке Windows, а не в коде. Включить обратно: Пуск → Параметры → Специальные возможности → Визуальные эффекты → «Эффекты анимации» → Вкл.

:hoverнаведение мышкой

«Когда мышка сверху». Пишется через двоеточие после бирки: .rabota:hover { ... } Внутри указывают только то, что меняется при наведении. Обычное состояние описано отдельно, выше.

transform: translateY(-5px)

Сдвинуть элемент по вертикали. Минус — вверх, плюс — вниз.

transitionпереход

«Меняйся не сразу, а за указанное время». transition: transform 0.35s — что меняем и за сколько. s = секунды. 0s резкий скачок · 0.35s плавно и приятно · 3s вязко, будто тормозит. Без этой строки анимации нет вообще — элемент прыгает мгновенно.

borderрамка

Три значения через пробел, всегда в этом порядке: толщина, тип, цвет. border: 1px solid var(--ramka); Типы линии: solid сплошная · dashed пунктир · dotted точки.

border-radiusскругление

Скругляет углы коробки. Чем больше число, тем круглее. 0 — острые углы. border-radius: 50% превращает квадрат в круг — половина от размера коробки. Так сделано круглое фото.

Два числа в отступе

padding: 26px 28px — первое число вертикаль (сверху и снизу), второе горизонталь (слева и справа). Одна сторона отдельно: margin-bottom, margin-top, padding-left и так далее.

:root

«Корень», самое начало документа. Тут объявляют переменные — палитра художника, все краски в одном месте.

Ctrl + U

Показать исходный код открытого сайта. Работает на всех сайтах — YouTube, Google, Instagram. Везде внутри тот же HTML.

Ctrl + F

Поиск по файлу в Блокноте. Незаменим, когда код длинный.

<!DOCTYPE html>

«Дальше идёт современный HTML». Самая первая строка файла.

<head>

«Голова» — служебная часть. На экране не видна.

<body>

«Тело» — всё, что видно глазами.

<script>

Внутри лежит JavaScript — программа. Ничего не показывает, а действует. <p> — текст для чтения · <style> — правила оформления · <script> — команды, которые выполняются. Ставят в самом конце <body>: скрипт работает с тем, что уже нарисовано. Поставишь наверху — запустится раньше и ничего не найдёт.

Голова или тело?

Простое правило: не видно на странице → в <head>. Видно → в <body>. <head> — инструкции для браузера, не текст для человека. Как техпаспорт машины: важен, но на дороге не виден.

Разделы страницы

Почти любой сайт устроен так, сверху вниз: header шапка — логотип, меню · hero первый экран — крупный заголовок, фото sections контент — о нас, услуги, работы · footer подвал — контакты, копирайт

Как читать длинный код

Каша получается, когда читаешь построчно. Читать надо блоками, по отступам слева — чем больше отступ, тем глубже вложенность. Как оглавление книги. Приём: найди <body> и смотри только на теги с одинаковым отступом. Это верхний уровень. Внутрь лезь, когда нужен конкретный кусок.

Слои на экране

Порядок в коде задаёт порядок слоёв: кто ниже в коде — тот выше на экране. Как стёкла одно над другим: холст с символами внизу, тёмная плёнка посередине, текст сверху.

<title>

Надпись на вкладке браузера. Лежит в <head>, поэтому на странице не видна.

<meta charset="utf-8">

Кодировка. Без неё вместо русских букв «кракозябры».

<h1> … <h6>

Заголовки. h1 — главный, дальше каждый мельче.

<p>paragraph

Абзац обычного текста.

<a href="...">anchor, ссылка

Ссылка на другую страницу. То, из чего вообще состоит интернет. <a href="https://google.com">Гугл</a> — href куда ведёт, между тегами то, что видно. Открыть в новой вкладке: добавить target="_blank". Так делают для чужих сайтов — человек уходит, а твоя страница остаётся открытой.

<ul> и <li>

<ul> — сам список (unordered list, маркированный), коробка для пунктов. <li> — один пункт (list item), каждый в своей паре тегов. Точки перед пунктами браузер ставит сам.

Три способа обратиться в CSS

Точка — класс. Решётка — id. Без знака — сам тег. h1 { } — ко всем тегам h1 на странице. .imya { } — только к тем, у кого class="imya". #matrica { } — к одному элементу с id="matrica".

margin: 0 auto

Приём для центрирования блока. Сверху и снизу ноль, по бокам «сколько получится» — значит поровну. Работает вместе с max-width: задаёшь ширину и ставишь по центру экрана.

index.html

Особое имя. Браузер открывает именно этот файл, когда заходит в папку сайта. «Главная страница».

Markdown.md

Простой язык разметки для текстов. Решётка # в начале строки — заголовок. Файлы КОНСПЕКТ.md и README.md написаны на нём.

README.mdread me

Визитка проекта. GitHub показывает её прямо на главной странице репозитория: что это, как поставить, как пользоваться. Открыл незнакомый проект — первым делом читай README.

Знаки Markdown

# — заголовок 1-го уровня, самый крупный. ## — помельче, до шести решёток. - в начале строки — пункт списка · **текст** — жирный. Пустая строка между блоками обязательна, иначе Markdown слепит их в один абзац.

Экранированиеescape

Обратный слэш \ перед знаком значит «не считай его командой, покажи как есть». \# покажет решётку текстом, заголовка не будет. Ловушка: при копировании текста из чата слэши цепляются сами к знакам #, *, -. После вставки всегда проверяй файл через Get-Content.

Git

Машина времени для файлов. Хранит все прежние версии, не только последнюю.

Git

Программа на твоём компьютере. Делает «фотографии» файлов, к любой можно вернуться. Аналогия: на столе один лист — текущий. В ящике стола Git сложил копии всех прежних.

Репозиторийrepository, «репо»

Папка, за которой Git следит. Внутри появляется скрытая папка .git — там история. Не трогать.

Коммитcommit

Одна сохранённая версия. Фотография файлов с подписью и номером.

Номер коммитаhash

Уникальный код фотографии, например ccf78ea. Хватает первых 7 знаков. По нему возвращаются к этой версии.

Три места файла

Аналогия — отправка посылки. 1. Твоя папка — вещи разбросаны по комнате. 2. Промежуточная зона (staging, индекс) — сложил нужное в коробку. 3. История Git — коробку заклеили и отправили.

Зачем «коробка»

Чтобы самому выбирать, что попадёт в фотографию. Поправил за день три разных вещи — сохрани их тремя коммитами с разными подписями. Потом легче искать.

git initinitialize

Поставить Git в папку. Делается один раз. Нужен не каждой папке — только там, где что-то создаёшь и переделываешь.

git status

Что у меня сейчас происходит? Ничего не меняет — как посмотреть на градусник.

git diff

Что именно изменилось с последнего сохранения. Игра «найди отличия», а git diff — ответы к ней. + строку добавили · − строку убрали · без знака — соседи для контекста.

git add имя-файла

Выбрать файл для сохранения — положить в чемодан. Сохранения ещё нет.

git add .

Добавить все изменённые файлы разом. Точка = «всё, что тут есть». Пробел перед точкой обязателен. Берёт всё подряд — сначала всегда git status, посмотреть, что берёшь.

git commit -m "подпись"

Сохранить в историю. -m = message, подпись. Кавычки нужны, чтобы Git понял: несколько слов — это одна фраза. Подпись коротко и по делу, отвечает на вопрос «что изменилось?». Без -m откроется редактор vim. Всегда пиши подпись сразу.

git log

Список всех коммитов, сверху свежие. Для каждого: номер, кто, когда, подпись. Короткий вид: git log --oneline · последние пять: git log -5

git show НОМЕР:файл

Посмотреть старую версию файла. Файл на диске не меняется. Пишется слитно, без пробелов вокруг двоеточия: git show ccf78ea:privet.html

git restore файл

Отменить свою правку — вернуть файл как в последнем сохранении. Отменяет все правки разом, искать их вручную не надо. Без имени файла не работает: fatal: you must specify path(s) to restore. Надо указать что восстанавливать.

git restore --source=НОМЕР файл

Прыгнуть в прошлое — вернуть файл как в старом коммите. Файл перезапишется, но пока правка закоммичена, её всегда можно достать обратно.

Ответы git status

Changes not staged for commit — файл правил, но в чемодан не клал. Changes to be committed — лежит в чемодане, ждёт коммита. nothing to commit, working tree clean — лучший ответ, всё в истории.

new file и modified

new file — Git видит файл впервые. modified — файл был раньше, ты его изменил.

Отчёт коммита

1 file changed, 8 insertions(+), 1 deletion(-) — считает строки, не буквы. Правку одной строки Git считает как две операции: убрал старую, добавил новую.

Git молчит

При успехе git add и git restore ничего не печатают. Нет ответа = нет ошибок.

Untracked filesфайлы без слежки

Файлы, о которых Git знает, но в историю их не берёт — пока не скажешь git add.

.gitignore

Список «вот это игнорируй». Git перестаёт замечать перечисленные файлы и не напоминает о них в git status. Имя начинается с точки, расширения нет. Точка в начале имени на Linux и Mac значит «скрытый файл». Сам .gitignore в историю коммитят — он полезен и другим людям в проекте. Правило действует только на файлы, которых Git ещё не знает. Кто уже попал в историю — по списку не выйдет. Поэтому .gitignore заводят сразу, до первого коммита.

Маски в .gitignore

Одна строка — одно правило. Звёздочка * значит «любое имя». musor.txt — этот файл · *.log — все файлы с расширением .log · temp/ — вся папка целиком. Звёздочка набирается Shift + 8 на английской раскладке.

HEAD

Указатель «я сейчас здесь». Показывает, на каком коммите и на какой ветке ты стоишь. В git log --oneline видно как (HEAD -> master).

Метки в git log

(HEAD -> master) — где я сейчас. (имя-ветки) — докуда доехала эта ветка. (origin/master) — докуда доехал GitHub. Если origin/master отстал — значит надо сделать git push.

Ветки

Черновик и чистовик. Пробуешь на дорожке, основная версия цела.

Веткаbranch

Отдельная дорожка для экспериментов. Правишь на ней — главная версия не трогается. Получилось — соединяешь. Не получилось — стёр ветку, потерь нет.

Ветка — не папка

По ветке нельзя ходить через cd. Папка одна и та же, меняется только содержимое файлов внутри неё. Git переписывает файлы на диске при переключении — как меняет декорации на сцене.

master

Главная ветка. Создаётся сама при git init.

git branch

Показать список веток. Звёздочка * — где ты сейчас.

git switch -c имя

Создать новую ветку и сразу перейти на неё. -c = create, «создай».

git switch имя

Перейти на существующую ветку. Понимает только имена веток — не файлов и не папок.

git merge имя

Влить ветку в текущую. Правило: сначала встань туда, куда вливаешь. git switch master → git merge proba Ответ Fast-forward — «перемотка вперёд», слияние без конфликтов.

git branch -d имя

Удалить ветку. -d = delete. Работа не пропадает: если ветка влита в master, удаляется только дорожка. Нельзя удалить ветку, на которой стоишь — как пилить сук под собой. Сначала уйди на другую.

Конфликты при слиянии

Git не угадывает, чья версия лучше. Честно говорит: решай ты.

Конфликтmerge conflict

Две ветки поправили одну и ту же строку по-разному. Git слить сам не может. Если ветки правили разные строки — сливает молча, без вопросов.

Ответ про конфликт

Auto-merging file.txt — пробую слить сам. CONFLICT (content): Merge conflict in file.txt — не смог, спор в этом файле. Automatic merge failed; fix conflicts and then commit — чини сам, потом коммить.

Метки конфликта

Git вписывает в файл служебные значки: <<<<<<< HEAD — начало спора, ниже моя версия. ======= — разделитель: выше моё, ниже чужое. >>>>>>> имя-ветки — конец спора.

Как чинить

1. Открыть файл, стереть все строки со значками. 2. Оставить нужный текст — можно одну версию, можно обе. 3. Сохранить обычным циклом: git add имя-файла → git commit -m "текст" Здесь git add значит ещё и «конфликт улажен, я разобрался». После него Git разрешит коммит.

GitHub

Git — программа на компьютере. GitHub — сайт в интернете. Git работает и без GitHub.

GitHub

Сайт, куда копируют папку вместе со всей историей. Облако для кода. Зачем: копия не потеряется · можно дать ссылку человеку · работодатели смотрят туда.

origin

Кличка адреса твоего репозитория на GitHub. Как «мама» в телефоне вместо длинного номера. У всех она одинаковая — так принято во всём мире. Разный за ней сам адрес.

git remote add origin АДРЕС

«Git, запомни этот адрес под кличкой origin». Один раз на папку.

git remote -v

Посмотреть, какой адрес записан. Две строки: (push) — отправить наверх, (fetch) — забрать вниз.

git push

Отправить свои коммиты на GitHub. Первый раз пишется длинно — git push -u origin master, дальше просто git push. -u = upstream, «запомни, куда отправлять». Git записывает связку master → origin/master и дальше подставляет её сам.

git clone АДРЕС имя-папки

Скачать репозиторий с GitHub себе. Приходят не только файлы, но и вся история. Адрес origin прописывается сам. Так работают с чужими проектами: нашёл на GitHub → clone → проект у тебя.

Два места

git commit сохраняет только на компьютере. git push отправляет на GitHub. Между ними бывает разрыв — Git пишет его во второй строке git status: ahead of 'origin/master' by 1 commit — надо сделать push. up to date with 'origin/master' — уже отправлено.

Public и Private

Public — репозиторий виден всем. Private — только тебе.

Вход из терминала

При первом push открывается окно Connect to GitHub. Пароль спрашивают один раз, дальше Git его помнит. Если кнопка «Sign in with your browser» не срабатывает — жми «Sign in with a code».

Сайт в интернете

Репозиторий — склад, там лежит код. Сайт — витрина, её видят люди.

Серверserver

Компьютер, который работает круглосуточно и раздаёт файлы другим по сети. От to serve — «обслуживать, подавать». Как официант.

Клиентclient

Тот, кто просит. Твой компьютер, когда ты открываешь сайт: «дай мне страницу» — «вот она».

Хостингhosting

Услуга: кто-то пускает тебя на свой сервер и разрешает положить туда файлы. Сервер — вещь, здание склада. Хостинг — аренда места в нём. Или так: сервер — квартира, хостинг — сдача её внаём.

GitHub Pages

Бесплатный хостинг от GitHub. Берёт файлы из твоего репозитория и показывает их как настоящий сайт. Включается один раз: Settings → Pages → Branch: master, папка / (root) → Save. Адрес: https://ИМЯ-АККАУНТА.github.io/ИМЯ-РЕПОЗИТОРИЯ/ Дальше следит за веткой master сам: сделал git push — сайт обновился через минуту.

Деплойdeployment

«Выкладка» — сборка и публикация сайта. На странице репозитория справа: Deployments ✅ github-pages значит «готово, опубликовано».

Три места, где живёт сайт

Аналогия — пошив одежды. 1. Папка на компьютере — мастерская, работаю руками. 2. Репозиторий на GitHub — склад, попадает через git push. 3. GitHub Pages — витрина, включил один раз в настройках.

Мастерская и витрина

Правил файл, обновил браузер — ничего не поменялось? Значит смотришь не туда. Посмотри на адрес в браузере: file:///C:/... — файл на компьютере. Мастерская, тут правлю. https://...github.io/... — сайт в интернете. Витрина, тут смотрят люди. Правка попадает на витрину только через git add → git commit → git push. Открыть местную копию: start .\index.html

Склад и витрина

Один и тот же проект, два адреса. github.com/имя/portfolio — склад. Видно код, файлы, историю. Для разработчиков. имя.github.io/portfolio — витрина. Видно готовую страницу. Для всех.

Порядок для нового проекта

Весь путь от пустой папки до сайта в интернете: mkdir имя → cd имя → git init → notepad .gitignore git add . → git commit -m "pervaya versiya" git remote add origin АДРЕС → git push -u origin master Новый проект — своя отдельная папка. Не создавай её внутри другого репозитория: Git начнёт считать её частью чужого проекта.

Ошибки и как их читать

Ошибаться нормально. Компьютер обычно сам подсказывает, что не так.

warning и error

warning — предупреждение, к сведению, можно жить дальше. error — ошибка, надо чинить. Часто вылезает warning: LF will be replaced by CRLF. Windows и Linux по-разному помечают конец строки. Игнорируем.

Имя "cl" не распознано

Опечатка в команде. Такой команды нет. Проверь по буквам.

'commin' is not a git command

Опечатка в команде Git. Он сам подскажет похожую: The most similar command is commit.

Nothing specified, nothing added

Забыл имя файла после git add.

No configured push destination

Сделал git push, а репозиторий на GitHub ещё не создан — Git не знает, куда отправлять. Лечится шагами 7–9 из шпаргалки «Новый проект с нуля» вверху страницы.

'add.' is not a git command

Потерялся пробел. git add. слитно — Git решил, что это название команды. Надо git add . Дальше цепочка разваливается: файл в коробку не попал → commit сохранять нечего → push отправлять нечего.

not a git repository

Git в этой папке не стоит, либо ты стоишь не в той папке. Проверь pwd.

'remove' is not a git command

Опечатка: remove вместо remote. Разные слова: remote — удалённый, адрес. remove — удалить.

Инструкция switch должна содержать…

Забыл слово git в начале. У PowerShell есть своё слово switch — он и перехватил команду. Правило: все команды Git начинаются со слова git.

«Нечего коммитить», а я правил файл

Значит правка не сохранилась на диск. Git не ошибается — он смотрит на файл, а не на открытое окно Блокнота. Проверь: Get-Content имя -Encoding utf8. Что там лежит на самом деле?

Открылся vim

Так бывает, если написать git commit без -m. Выход: Esc, потом :q!, потом Enter. Коммит отменится — просто повтори с подписью.
